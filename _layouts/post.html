{% comment %} Related-post selection. The previous implementation filtered on "shares at least one tag" and then took the head of site.posts, which is reverse-chronological. Because `ai-strategy` sits on 41 of 46 posts, that filter admitted nearly everything, so the head of the list did all the work: every post linked to the two newest posts. Measured on production 2026-09-14, 86 of the 92 available link slots landed on two URLs and 42 of 46 posts received zero inbound links. The sink also moved, so each new post drained the previous one, permanently concentrating link equity on the page with the least accumulated authority. Two changes fix it: 1. RANK BY SHARED-TAG COUNT, not by a boolean. Candidates sharing 2+ tags are preferred over those sharing exactly 1, so the broad tags stop deciding the outcome on their own. 2. ROTATE THE WINDOW. The start index is derived from the post's own date and title length rather than always being 0, so the 92 slots spread across the corpus instead of piling onto whatever shipped last. Deterministic, so builds stay reproducible and the same post always renders the same pair.
